# Claude Code Single-User CLI Parity Matrix

> Native-only status: this matrix records the historical clean-room behavior
> target and fixture evidence. The active Praxis runtime has one data plane
> (`~/.praxis` or `PRAXIS_HOME`); it does not read or write Claude Code session,
> settings, MCP, hook, permission, or worktree directories. Historical live
> Claude gates are retained as evidence only and are not CI/runtime
> dependencies.

## Scope

The core-design target is Claude Code 2.1.237. The broader command/TUI inventory
retains its native runtime contract and focused regression fixtures. Praxis remains a clean-room, provider-neutral
implementation: observable behavior, design boundaries, and state flows are
authoritative, while source code is not copied verbatim.

Permanent exclusions are limited to organization, tenant, RBAC, subscription
authentication and billing, enterprise gateway, IDE/Desktop/mobile clients,
Remote Control, Claude Desktop migration/import, and hosted-only product
surfaces. Explicitly classified non-goals extend that boundary to the
subscription-bound integration, campaign, hidden maintainer diagnostic, and
build-experimental commands below. A missing feature cannot be declared
complete because another Praxis surface is similar.

Evidence levels:

- **Live**: exercised against installed Claude Code 2.1.208 and Praxis.
- **Fixture**: isolated unit/integration or installed-package contract test.

The 2.1.208 executable is the pinned CLI/TUI/shared compatibility
qualification baseline. Newer Claude releases are observation-only drift
lanes and cannot replace a pinned baseline qualification run.

Dispositions, per the accepted developer-core command inventory:

- **Required**: known missing developer-core work and a completion blocker;
  only these entries block developer-core closure.
- **Deferred**: optional, demand-driven single-user work; not a core
  completion blocker.
- **Excluded**: evidence-backed surface outside the Praxis product boundary,
  including the permanent exclusions above and the explicitly classified
  command groups below.
- **Missing**: required implementation or executable evidence is absent.

Accepted inventory dispositions (`included | required | deferred | excluded`):

- **Required**: none. Stage 141 closed `/cost`; Stages 144-147 closed
  interactive `/doctor` with structured installation diagnostics, real TUI
  projection, progressive update resolution, and installed-package PTY
  evidence.
- **Deferred**: `/advisor`, `/fast`, `/stats`, `/insights`, `/voice`.
- **Newly excluded**:
  - subscription-bound integration: `/chrome`;
  - campaign: `/think-back`, `/thinkback-play`;
  - hidden maintainer diagnostic: `/heapdump`;
  - build-experimental: `/buddy`, `/proactive`, `/brief`, `/assistant`, `/torch`.
- Existing permanent exclusions are unchanged; deferred and newly excluded
  commands are not required parity work.

## Final audit status

The supported core-design scope is covered by contract-level native fixtures. The
credential-free command and shared-data surface remains closed against its
historical Claude Code behavioral reference, while Praxis itself uses only the
native `~/.praxis` data plane. Interactive TTY parity remains partial, as stated
in the matrix above. Native session discovery, resume, fork, compaction,
sidechains, hooks, MCP, permissions, and scheduled state are validated through
unit, integration, package, and deletion gates. Non-native transcript files and
unsupported schema versions fail closed without migration or mutation.
Enterprise, desktop, remote-control, and subscription-auth surfaces remain
excluded by scope.

The required GitHub `CI` status now runs the native quality, boundary,
production-audit, package, and platform gates without installing or invoking a
Claude executable. Historical baseline rows above remain useful behavioral
evidence, but the removed compatibility suite, migration probes, and live
Claude data-plane lanes are not runtime or release dependencies. Native
transcript/session/resource paths are covered by focused fixtures and the
installed-package/deletion gates; unsupported external transcript formats fail
closed without migration or mutation.
Release automation does not expand or alter product parity scope.
